# Telemetry on one shared `gauntlet/telemetry` branch, with shape-ticket, gatekeep-pr and check-delivery leg records

**Goal:** Every gauntlet cost record - the brainstorm-to-ship run record and a new per-session leg record for shape-ticket, gatekeep-pr and check-delivery - lands as an immutable file on one orphan `gauntlet/telemetry` branch pushed to `origin` (or `piGauntlet.telemetry.remote`), written and read through git plumbing without ever touching the checkout, so no telemetry file ever rides a working branch and every reader shares the corpus under the hood.
**Amend-grant:** every later spec amendment in this flow (corrected facts, paths, verification lines, and scope, acceptance-criteria, or public-contract edits alike) applies without asking; only a redraw (changed problem statement, component added, removed, or re-bounded) still stops for you, and the grant never stands in for a spec approval.
**Engine:** loop
**Predecessor:** doc/specs/2026-09-25-gauntlet-bound-telemetry.md - supersedes its on-disk record, seal and guard sections; its binding lifecycle and gatekeep-pr separation stay. Path classification and seal/index discovery belong to doc/specs/2026-09-30-spec-dir-discovery.md and are not touched.
**Ticket:** #124

## Problem

The run recorder (`extensions/telemetry.ts`) arms only on `phase_tracker start brainstorm` and discards usage while unarmed (`extensions/telemetry.ts:235-240`), so a shape-ticket, gatekeep-pr or check-delivery session writes no cost record at all. The run record it does write lives as an untracked file in the checkout, hidden through `info/exclude`, and is committed on the feature branch by the seal (`extensions/lib/vcs.ts:65-73`, `skills/finishing-a-development-branch/SKILL.md:248`), so it reaches `main` only when that branch lands, and a dozen guards exist only to keep that file out of the way: the exclude writer, `git add -f`, a jj `file track --include-ignored` branch, the `--invert-grep '^telemetry: '` commit-count filter (`extensions/lib/telemetry-diff.ts:60`), the `':!<telemetry.dir>'` carve-out in the finish skip proof (`skills/finishing-a-development-branch/reference/verification-set.md:22`), the seal's restore-on-failure path, three finishing pitfalls and a red flag, and the `scripts/ci.mjs:354-363` wording pins. Readers (`gauntlet-performance`, `gauntlet-spec-index`) read only the local checkout; the spec index even hardcodes `.pi/gauntlet/telemetry/<spec>.yaml` and ignores `telemetry.dir` (`src/bins/gauntlet-spec-index.mjs:354-356`). Nothing links a PR verification or a delivery check to its ticket, and `.github/workflows/test.yml:3-5` runs on push to every branch, so a telemetry branch would trigger CI today.

The reporter's spend figures ($1,858 of $7,068 across three weeks; per-leg shares) are requester measurements, not verified and not design inputs. Two dependencies the design relies on are not exercisable before approval and go to `## Tests`: git plumbing in a jj-colocated workspace, and the two-clone push race.

Framing: kept - the user answered A (in-scope) on `Readers refresh themselves` on the condition that push-on-read is cheap; it is one shared helper used by writers and readers alike. The user's stated priorities: simple, not error-prone code; sharing works with no developer step; losing a rare stranded record is acceptable; pi-gauntlet works without any telemetry at all.

## Design

### Branch library - the only git seam

Add `extensions/lib/telemetry-branch.ts` (bundled into the three bins by `scripts/build-bins.mjs`, like `vcs.ts` today). It runs git through the bounded runner `vcs.ts` already has: export today's module-private `runBinary("git")` (`vcs.ts:15`; 10 s default timeout, prompts disabled) as `gitRun` - one runner, no duplicate. `checkoutOf` stays in `checkout.ts`, which owns it. Every caller (recorder, seal, both bins) checks `telemetry.enabled` before calling the library; with `enabled: false` nothing is fetched, pushed, or read. Exports:

- `syncTelemetryBranch(repoDir, { remote, writes: [{ path, bytes }] })`: resolve the git common dir; `git fetch <remote> +refs/heads/gauntlet/telemetry:refs/remotes/<alias>/gauntlet/telemetry` best-effort. Write base: `refs/heads/gauntlet/telemetry` when it exists, else the fetched ref, else an orphan root. For the writes: `hash-object -w` each blob, then on a temp `GIT_INDEX_FILE` `read-tree <base>` (skipped for the orphan root), `update-index --add --cacheinfo 100644,<blob>,<path>`, `write-tree`, `commit-tree -p <base>` (no `-p` for the root) with subject `telemetry: <path>`, `update-ref refs/heads/gauntlet/telemetry`. Pending commits are `rev-list refs/heads/gauntlet/telemetry ^refs/remotes/<alias>/gauntlet/telemetry` - every local commit when the fetched ref is missing or the two roots are unrelated (first-use race). When pending commits exist (with or without writes - the latter is refresh's stranded push), `git push <remote> refs/heads/gauntlet/telemetry:refs/heads/gauntlet/telemetry` without force. On rejection: fetch again, replay each pending commit in order onto the fetched tip (one `commit-tree` per pending commit: the parent's tree plus that commit's blobs, later blob wins on a shared path), `update-ref` to the replayed head, push once more. On the second rejection, or any failure after a local commit exists, return `{ committed: true, pushed: false, reason }` with every pending commit still on the local branch; the caller prints `telemetry: not pushed (<reason>)` and continues with exit 0. A failure before a local commit exists (`hash-object`, `read-tree`, `write-tree` or `commit-tree` fails - including a missing git identity) returns `{ committed: false, pushed: false, reason }`: no local commit exists and the caller keeps its source file. The temp index file is deleted on every path; the checkout's index and working tree are never read or written. `remote` is `origin` by default or the `telemetry.remote` URL (fetch and push by URL, with the alias `telemetry` for the tracking ref; no `git remote add`).
- `readTelemetryBranch(repoDir, { remote, prefix })`: first `syncTelemetryBranch` with no writes (fetch, then push pending commits under the same one-retry rule); after a successful push fetch once more so the fetched ref includes them. Then `ls-tree -r` and `cat-file` under `<prefix>` on `refs/remotes/<alias>/gauntlet/telemetry` only - the local branch is pending-push storage and never a read source. Returns `{ records: [{ path, bytes }], warning }`: `warning` names the fetch failure (the last fetched ref is served), or is `no telemetry ref fetched yet` with `records: []` when the remote ref was never fetched (also after a local-only offline first seal), and folds in `telemetry: not pushed (<reason>)` when the pending push failed. It never throws; callers degrade on an empty `records`.
- `trackerRefs(text)`: the one tracker-ref grammar, shared by the seal's `tickets:` and the settlement-row parser: `#N`, `owner/repo#N`, `[A-Z][A-Z0-9]+-\d+`, a tracker URL (`/issues/N`, `/pull/N`, `/issue/<KEY>-<N>`), and the filename slugs brainstorming writes (`skills/brainstorming/SKILL.md:172`: `gh-<N>` maps to `#N`, `<KEY>-<N>` is kept). The overrides `## Issue tracker` `refs:` entry (`.pi/gauntlet-overrides.md:9`) stays prose documenting the convention; it is never interpreted as a pattern.

Remove `commitRecordFile`, `recordSealed` and the jj `file track --include-ignored` branch from `extensions/lib/vcs.ts`; `vcsFor`, the git/jj detection and the newly exported `gitRun` stay.

### Repo identity

`repoIdentity(repoDir)` in the same library: parse `git config --get remote.origin.url` - scp form (`git@host:path`, this repo's `git@github.com:jjuraszek/pi-gauntlet.git`), `ssh://host[:port]/path`, `https://host/path` - take the path, strip a leading `/`, a trailing `/` and `.git`: `jjuraszek/pi-gauntlet`. A nested namespace keeps every segment (`group/sub/name`), so two distinct product repos never map to one identity. Without origin, the `repo:` value of the first-found overrides `## Issue tracker` section; without that, `local/<primary directory basename>`. The value is the record's `repo` field, the branch path prefix, and the grouping key of every gauntlet-performance table, for every tracker and also when `telemetry.remote` is set (identity still comes from the product repo's origin). The seal stamps it on every new run record; `--migrate` stamps it on records lacking it.

jj-only workspaces (no `.git`, `checkout.ts:4-5`) have no git common dir and no object store: the in-progress record lives at `<jj root>/.jj/gauntlet/telemetry/<spec path with .md -> .yaml>`; recorder, seal and `gauntlet-resume/reference/seed.md` resolve that one path when `git rev-parse --git-common-dir` fails and `jj root` succeeds. The seal returns before any branch plumbing, keeps the file there, and prints `telemetry: not pushed (jj workspace: no git remote)`.

### Seal (`src/bins/gauntlet-telemetry-seal.mjs`)

Read the in-progress record at `<git common dir>/gauntlet/telemetry/<spec>.yaml` (jj-only: the `.jj` path above; `recordPathFor` in `telemetry-paths.ts` retargets to the shared path, replacing today's checkout read at `seal.mjs:141`). ## Errors and edge cases

- `telemetry.enabled: false`: no leg arming, no fetch, no push, no guard read - the recorder, seal and both bins check `enabled` before any branch operation; `--dir` fixture reads never depended on it.
- Leg skill inside a bound run session: charged to the run; no leg record.
- No origin, or jj-only: the commit lands on the local `gauntlet/telemetry` branch (git) or the record stays at `<jj root>/.jj/gauntlet/telemetry/<spec>.yaml` (jj-only); line `telemetry: not pushed (no remote)` / `(jj workspace: no git remote)`.
- Push rejected: one refetch, replay each pending commit, push; second rejection prints `telemetry: not pushed (<reason>)`, every pending commit kept on the local branch for the next sync from that checkout (seal, leg write, or any reader's refresh).
- Local commit cannot be created (no object store, `commit-tree` without a git identity): `telemetry: not pushed (<reason>; record kept at <path>)`; the source file stays for the next seal; a leg record with no source file is lost - accepted (rare stranded record).
- No in-progress record at seal (recorder never armed): `no telemetry run`, exit 0, the landing proceeds; an unparseable record likewise never blocks the ship.
- Fetch failure or unreachable remote: bounded by the 10 s `gitRun` timeout; readers and guard use the last fetched remote ref; the local branch is never a read source; with no fetched ref (including a local-only offline first seal) readers serve an empty corpus and the guard passes with one notice.
- Same path written from two clones: the later push's blob wins; no merge.
- gatekeep-pr set mode: a per-PR retirement's `gauntlet: retired #<N> - <reason>` first line never matches the terminal regex, so a stopped PR followed by continuing siblings and a cleanup pick still yields one record with every PR's row.
- Session ends without a settlement line: nothing written. Lines below the marker that are not settlement rows (`worktree: done`, headings, prose) are skipped; a `tracker: none` ref is stored as typed. Two settlements in one second in one session would overwrite the first file - accepted, unreachable with a model turn between.
- `telemetry.dir` in settings: one resolver warning naming `telemetry.remote`; the key is ignored.
- `--migrate` run twice: the second run queues nothing and creates no commit.
- gatekeep-pr `<pr>:` lines contain no telemetry word; the `ci.mjs:366` ban stays.
