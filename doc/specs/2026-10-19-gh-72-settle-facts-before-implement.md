# Settle facts before implement: baseline provenance, contract decisions, lookup before asking, eval acceptance

> **Superseded by:** [doc/specs/2026-10-26-selective-baseline-rerun-on-amend.md](./2026-10-26-selective-baseline-rerun-on-amend.md) - D2 "same base" retention condition (retain rule, rows 157/171, dependent execution-only statements) only

**Goal:** The brainstorm records implicit environment dependencies as checked premises, the plan carries a base-commit test result for every task and names every contract decision it makes, the implement phase looks a fact up before asking the human for it, and the eval runner passes an unplanned improvement with a visible label instead of blocking on it.
**Amend-grant:** every later spec amendment in this flow (corrected facts, paths, verification lines, and scope, acceptance-criteria, or public-contract edits alike) applies without asking; only a redraw (changed problem statement, component added, removed, or re-bounded) still stops for you, and the grant never stands in for a spec approval.

Reading of row 3 (Design clause D2): "fails on the base commit" is satisfied by the plan-writer running the command on base, withholding the `baseline:` bullet, and writing one `## Open Questions` row whose first line carries task, command, base SHA, exit code, and a one-line result summary. ## Design

Five components, one per phase where the fact is cheapest to settle, plus the eval acceptance rule the first four are verified under.

### D1. Brainstorm: implicit-dependency premise check

- `skills/brainstorming/gatherer.md` scout task template gains one required recon item: `Implicit dependencies: <item> - <how checked> - <found | not found | not checkable: <why>>`, one line per environment dependency the request relies on without naming it - a file a kept component loads, a binary, a database extension, a fixture, a data subset a verification step names - or `Implicit dependencies: none found - traced <components, steps>`. The scout discovers the item by tracing the loader/caller in source and by tracing every repro and verification step the request states (a dump restore, a performance check, a CLI invocation); a path or capability the request mentions is a claim to check, not proof it exists.
- `skills/brainstorming/SKILL.md` sec 3 premise note gains one sentence: an implicit dependency the recon found missing or not checkable is a corrected or unverified premise respectively, stated in the premise note with its lookup and result, and carried into `## Problem`. No new question type; no stop. The holds-statement names the traced dependencies among the things checked.
- `skills/brainstorming/SKILL.md` sec 4 (the approaches message, a separate message after the premise note) gains one sentence: restate each implicit dependency the premise note recorded as missing or not checkable, with its lookup and result, before the approaches (AC row 1 names the approaches message and the spec, not only the premise note).
- Skills stay generic: no tool names in skill text; the lookup is "the lookup the repo or spec names".

### D2. Plan: baseline provenance

- `agents/plan-writer.md` frontmatter `tools:` becomes `read, grep, find, ls, bash, write, plan_check`. The body gains: `bash` is for the provenance commands (`git rev-parse`, `git status --porcelain`, or their jj forms below) and running the plan's own `Tests:` commands against the worktree; no edits to tracked files, no commits, never `stash`, `checkout`, `restore`, `clean`, nor a jj command that changes the working copy or its revisions (`new`, `commit`, `abandon`, `restore`, `squash`).
- `agents/plan-writer.md` steps 5-7 and `skills/writing-plans/SKILL.md` Self-Review **Deterministic checker** gain the terminal rule: baseline evidence is never authored. A substantive `open-questions` finding and every `baseline-line` finding (missing bullet, malformed, misplaced, invalid `skipped`/`pass via`, differing SHAs) are repaired only by a Baseline pass that runs the command - never by writing a `pass` or `skipped` bullet, never by deleting or rewording a row by hand. The `## Open Questions malformed` reason is a repair target: the child normalizes the section into `- ` rows without changing any row's substantive text. The child fixes every other finding; when a substantive row remains it replies `OPEN QUESTIONS <abs plan path>` without a passing check; a plan with no row omits the section and replies `PLAN WRITTEN`.
- Row ownership: Baseline regenerates every baseline-form row (`- Task N: ... fails`, `dirtied tracked source`, `- Baseline: ...`) from the current collection on each pass - a resolved row disappears, a new one appears, and the `blocked:` continuation lines are recomputed. Contract rows (D3) stay until answered per the existing `Findings:` answer rule. The section is omitted when neither kind remains. `agents/plan-writer.md:26` "keep everything the block does not touch; remove the section when every question is answered" gains "except baseline rows, which Baseline owns and regenerates".
- `agents/plan-writer.md` `Findings:`/`Amend:` re-dispatch: run step 1 of Baseline once for the current base; rerun every command whose bullet is missing, whose recorded SHA differs from that base, or whose command text changed; keep a bullet only for an unchanged command on the same base; a `Findings:` row `rerun baseline` reruns every command. Baseline SHAs are never rewritten without a rerun.
- `skills/writing-plans/SKILL.md` gains a step **Baseline** inside `## Self-Review (Before Handoff)`, before the Deterministic checker bullet (the section headings stay as they are so eval slices anchor in both arms):
  1. Provenance. `BASE=$(git -C "<abs worktree path>" rev-parse --short HEAD)` (the spec commit; the plan is not yet committed). `git -C "<abs worktree path>" status --porcelain` prints `XY <path>` with worktree-relative paths and `??` for untracked files; match paths against the worktree-relative form of every allowed workflow edit: the plan path and the spec path on every dispatch, plus on an `Amend:` re-dispatch every path the parent lists under `In-flight:` in the `Amend:` block (the amended spec, the staged deliverables of an in-place wave repair, per `amendment-surface.md` section 5 and `subagent-driven-development/SKILL.md:173`). The parent lists them from its own porcelain read; the child never infers the set. Any other entry, tracked or `??` -> one `## Open Questions` row `- Baseline: worktree dirty on <BASE>: <paths>` and no test runs (nothing is reverted). Allowed in-flight paths outside the spec and plan directories are source edits and could change what a test command exercises: when any exists -> one row `- Baseline: in-flight source edits on <BASE>: <paths>` and no test runs (a result against modified source would not be a base-commit result). Doc-only allowed edits cannot affect a test command and do not block. A plain jj workspace (no `.git`; `extensions/lib/vcs.ts` `kind: "jj"`) uses the equivalent procedure: `BASE=$(jj -R "<abs worktree path>" log -r @- --no-graph -T 'commit_id.short()')` (the parent of the working-copy revision, which holds the uncommitted plan the way git's working tree does) and `jj -R "<abs worktree path>" diff --summary` as the dirty read (one-letter status plus worktree-relative path; jj snapshots new files, so a new path appears as `A`), classified identically.
  2. Per `Tests:` command bullet, split it into segments on the contract's separators (`&&`, `||`, `;`, `|`; `plan-contract.md:30`) and classify each segment's anchor tokens (a `Test:` path alone or with a `::`/`#`/`:` filter) and selectors independently:
     - every anchor in every segment is a `Create:` path of some task -> append `- baseline: <BASE> skipped - <path> created by this task` (one path per created anchor, `, `-joined);
     - no segment holds a created anchor or an introduced selector -> run `(cd "<abs worktree path>" && <command>)` unchanged; pass -> append `- baseline: <BASE> pass`; fail -> append nothing and collect `(task, command, exit code, last 20 output lines)`;
     - otherwise derive the base command segment by segment: drop every token that is a created anchor; strip an introduced attached filter down to its path; drop an introduced flag selector together with its value token; a segment left without an existing `Test:` anchor of the task is dropped whole; the base command is the surviving segments joined by their original separators. It must keep at least one segment, and every surviving segment must anchor an existing `Test:` path of the task and no `Create:` path, else the bullet is `skipped` as in the first form (this happens only when every anchor was created). Run the base command; pass -> append `- baseline: <BASE> pass via `<base command>``; fail -> collect as above against the original `Tests:` command, with the base command recorded alongside.
     An introduced selector is an attached filter string or a flag selector pair (`-k <expr>`, `-t <name>`, `-e <name>`, `-n <name>`, `--grep <name>`, `--test-name-pattern <name>`) whose filter or name string appears verbatim in a test name the task's own steps say they add; a selector the task's steps do not name stays in the command, which then runs unchanged. Pass means exit 0 and the runner's summary reports at least one test executed; a non-zero exit is a failure, and an exit-0 run whose summary reports zero tests (`pytest` exits 5; `node --test` with a non-matching pattern and `jest -t` exit 0 with `# tests 0` / `No tests found`) is a failure recorded as `exit <n>, no tests ran`. Non-zero output is never read as a harmless skip.
  3. After each run: the porcelain read and `BASE` read of step 1 again. A new entry with a tracked status outside the allowed set, a new `??` entry (jj: `A`) that is a `Create:` path of some task or a `Test:` anchor of the plan (a new source file the plan owns), or a moved `BASE` -> collect `(task, command, "dirtied tracked source: <paths>" | "HEAD moved to <sha>")`, stop running further commands, and record every unrun command; nothing is reverted. Any other new `??` entry is a disposable generated artifact (a coverage file, a snapshot dir): it never stops the pass and never invalidates the result; the bullet records it, `- baseline: <BASE> pass - artifacts: <path>[, <path>]` (also after a `pass via` form), and nothing is deleted.
  4. Any collected item -> write the plan with `## Open Questions` at the top, one row per item. Row grammar: first line `- Task N: `<command>` fails on <BASE> (exit <n>): <one-line result summary>` quoting the original `Tests:` command; continuation lines indented under the row: `ran: `<base command>`` when the run was derived, then the last 20 output lines in a fenced block. Contamination: `- Task N: `<command>` dirtied tracked source on <BASE>: <paths>` (or `moved HEAD to <sha>`). Global rows: `- Baseline: worktree dirty on <BASE>: <paths>` and `- Baseline: in-flight source edits on <BASE>: <paths>`. A contamination or global row lists every command it blocked as continuation lines `blocked: Task M `<command>``, so each missing bullet is attributable to its cause. Reply `OPEN QUESTIONS <abs plan path>`.

### D5. Eval: unplanned improvements pass with a label

- `eval/lib/judge.mjs` `deriveLabels`: any observed `fails -> holds` move that does not match a listed intended transition - the fact is unlisted, or `intent.md` lists it in the opposite direction (`holds -> fails`) - is labeled `unplanned improvement` (the `unexplained change` label is removed; no new blocking label for an observed improvement, because an intent disagreement is not an observed regression). `cellVerdict`: `regressed` on any `regression`; else `improved` on any `intended change` or `unplanned improvement`; else `unchanged`. `VERDICT_ORDER` is unchanged. `intent.md` keeps its role of explaining the intended effect; it is never required to predict every improvement, and `intended change` keeps its label for listed facts.
- `eval/run.mjs` `confirm` runs only on `regressed` and keeps `regressed` only when a `regression` label reproduces on the same fact; an `unplanned improvement` on the confirmation replay never confirms a regression. Improvement-only cells skip confirmation.
- `eval/run.mjs` `judgeEntry` on a cache hit (`judgmentCurrent` true): keep the stored per-fact baseline and candidate outcomes, feedback, and timing; first re-derive labels and the cell verdict from those outcomes under the current policy. A cell whose re-derived labels hold no `regression` (improvement-only, including a legacy cell stored `regressed` or `inconclusive` because its only non-held move was `unexplained change`) becomes `improved` directly - its stored confirmation, if any, is ignored, no model call. Only a cell still holding a `regression` label consults its stored confirmation: it reproduces when a `regression` label reproduces on the same fact under the current labels; a stored confirmation that reproduced no regression (only an improvement, or nothing) leaves the cell `inconclusive` because the regression was never re-checked; a regression cell with no stored confirmation takes the existing `confirm` path. No model call, no replay, no re-judge for a classification change; evidence whose identity no longer matches takes the existing refresh path. A stored judgment missing per-fact outcomes, or stored as `error`, is not reclassified: it keeps its verdict and the existing recovery path.
- `eval/run.mjs` persistence: a reclassified candidate record is written through `writeChanged` when its labels or verdict changed; the report is regenerated when any cell's verdict or labels changed, even with zero model calls (`called === 0`). A second identical run makes no further changes. The `writeChanged` -> `writeRecord` call on this cache-hit path has no catch today (`eval/run.mjs:35-41, 270-276, 339` set `persistenceError` only when `refreshWriter` throws inside the `--refresh-judgments` branch); the reclassification write gains its own catch that sets the same persistence error, exits 1, and leaves `report.md` unchanged.
- `eval/lib/report.mjs` renders `unplanned improvement` as a per-fact label like every other; no new column.
- `eval/README.md` label table replaces `unexplained change` with `unplanned improvement` (non-blocking, `improved` verdict), rewrites line 137 so an opposite-direction listed move is also `unplanned improvement`, states that confirmation applies to `regression` only, and states that a cache hit re-derives labels and verdicts under the current policy without a model call. The sentence "Do not add one merely to silence a disputed judgment or because a rerun passed" stays.

### Data flow

scout `Implicit dependencies:` -> premise note -> approaches message -> spec `## Problem`. plan-writer `bash` -> provenance check -> `baseline:` bullets -> `plan_check` stamp, or `## Open Questions` rows (regenerated each pass) -> `OPEN QUESTIONS` reply (terminal, no repair) -> parent step 6 (`fails` rows: fix-first / narrow / amend; global rows: restore-and-rerun; contract rows: answers path) -> `Findings: rerun baseline` re-dispatch -> stamp. parent lookup across documented locations -> `Searched:` -> stop note -> human only when every location is absent or needs credentials. eval: stored or fresh per-fact outcomes -> `deriveLabels` (`unplanned improvement` non-blocking) -> `cellVerdict` -> `confirm` on `regressed` only -> record + report -> exit.

## Errors and edge cases

| Case | Behavior |
|---|---|
| `Tests:` command fails on base | no `baseline:` bullet; `## Open Questions` row with task, original command, SHA, exit code, summary, `ran:` line when derived, 20-line tail; child replies `OPEN QUESTIONS` without repair rounds; parent offers fix-first / narrow / amend; the only new plan-phase human stop, fired only when the base itself is broken |
| every anchor of the command is a `Create:` path | `- baseline: <sha> skipped - <paths> created by this task`; checker validates the paths against `Create:` and the command |
| command mixes existing and created anchors, or carries a selector naming a test the task introduces | base command derived per segment over the existing anchors runs; `- baseline: <sha> pass via `<base command>``, or a failure row quoting the original command with `ran:` |
| compound command whose one segment anchors only a created path | that segment is dropped whole; the base command keeps the other segments, each still anchored; a `pass via` whose segment lost its anchor is a `baseline-line` finding |
| selector the task's steps do not name (`-k`, `-t`, attached filter) | not introduced; the command runs unchanged; a zero-test outcome is a failure row |
| exit 0 with zero tests executed | failure row `exit 0, no tests ran` (runner summary read; `pytest` exit 5 is non-zero already) |
| `skipped` bullet names a path that is not a `Create:` path, or `pass via` anchors a created path or a segment without an existing anchor | `baseline-line` finding; repaired only by a Baseline pass |
| `baseline-line` finding of any reason during the child's fix rounds | not authored; the child runs Baseline for that command (or leaves it blocked under its global row) and never writes a `pass`/`skipped` bullet by hand |
| `- none: <category>` task | no `baseline:` bullet; one present -> `baseline-line` finding |
| `baseline:` SHAs differ within one plan | `baseline-line` finding `baseline SHAs differ: <a>, <b>`; the child never hits it because a re-dispatch reruns changed-SHA commands |
| plan path and spec path uncommitted at Baseline (every dispatch) | allowed workflow edits; not dirt; tests run |
| `Amend:` re-dispatch with in-flight doc-only paths listed by the parent | allowed; tests run; no stop |
| `Amend:` re-dispatch with in-flight source paths (staged wave-repair deliverables) | `- Baseline: in-flight source edits ...` row with `blocked:` lines; no runs; the parent clears them through the wave's own commit step and re-dispatches `Findings: rerun baseline`; no human stop unless the paths are not the parent's work |
| worktree dirty before Baseline (any other path, tracked or `??`) | `- Baseline: worktree dirty ...` row with `blocked:` lines; no runs; no revert; restore-and-rerun (human names what happens to the paths); the three-option menu is not offered |
| test command dirties tracked source, writes a `Create:`/`Test:` path, or moves HEAD | contamination row naming the paths with `blocked:` lines for unrun commands; no revert; restore-and-rerun |
| test command leaves an untracked generated artifact (coverage file, snapshot dir) | recorded on the bullet as ` - artifacts: <paths>`; the pass stands; nothing stops, nothing is deleted |
| plain jj workspace (no git HEAD) | the jj provenance form: `BASE` from `jj log -r @-`, dirty read from `jj diff --summary`, same classification; stamps like git |
| command cannot run in the plan-writer's host (allowlist, missing runtime) | treated as a failure -> row with the error; a command the plan-writer cannot run, the implementer cannot either |
| command hangs | out of scope; no plan-writer timeout rule (Out of scope) |
| `## Open Questions` absent, or exactly `- none` | passes `open-questions`; child replies `PLAN WRITTEN`; parent does not wait; a restored plan in that state takes `PLAN WRITTEN` handling too |
| `## Open Questions` with substantive `- ` rows | one `open-questions` finding per row quoting its first line; terminal in the child; parent branches on each row's form |
| `## Open Questions` holding prose or a table | `open-questions` malformed finding; the child rewrites it as rows without changing any row's substantive text (the one open-questions repair target) |
| failure tail in a row's fenced block contains `TODO` / `etc.` | no `placeholder-scan` finding; the block is masked; the same token in authored prose still fails |
| `Findings:`/`Amend:` re-dispatch after HEAD moved, or `Findings: rerun baseline` | one new base; every command with a missing bullet, a different SHA, or changed text reruns (all of them on `rerun baseline`); baseline rows regenerated; a resolved failure row disappears |
| fix-first after the fix lands | worktree rebased or merged onto the new base per `using-git-worktrees`; `Findings: rerun baseline` re-dispatch; stamp when everything passes; same session directly, otherwise through resume's baseline continuation |
| spec silent on a boundary, source settles it | plan-writer writes `Decision:` in the task; no question |
| spec silent and source cannot settle | `Open Questions` row (human, answers path) - this is "the spec was wrong", the one allowed new stop |
| plan stamped before this release, resumed after | `baseline-line` finding; resume's baseline continuation re-dispatches the plan-writer, rechecks, and returns to the restore route with the snapshot's task statuses; never the fresh-plan `init` |
| resumed plan whose Baseline rerun still fails | the step 6 menu or restore-and-rerun, phase `plan` retained, no `plan_tracker init` |
| scout failed (degraded draft) | main loop's own recon supplies the implicit-dependency check; holds-statement names it |
| implicit dependency not checkable (credentials, remote) | premise note lists it as unverified with the attempted lookup; approaches message restates it; Open Questions or stated assumption, no stop |
| implicit dependency missing | premise note and approaches message both name the file or capability, the lookup, and the result; carried into `## Problem` |
| fact ask, first documented location misses, second holds the artifact | both lookups recorded; re-dispatch with the found location; no stop note |
| fact ask, every documented location absent or a remaining one needs credentials | stop note with one `Searched:` line per location; options supply-or-amend, never a location question |
| lookup tool absent at implement time | `Searched: <tool> - not available`; the ask proceeds via the stop note |
| decision ask under `NEEDS_CONTEXT` or `BLOCKED`, sequential or wave | no lookup; existing answer-or-escalate path |
| `escalationLoop` "approve another fix round" | decision ask; no `Searched:` requirement, unchanged |
| eval: unlisted `fails -> holds` | label `unplanned improvement`; cell `improved`; no confirmation; exit 0 when nothing else blocks |
| eval: `fails -> holds` on a fact `intent.md` lists as `holds -> fails` | `unplanned improvement`, visible in the report; `improved`; no blocking label |
| eval: listed `fails -> holds` | `intended change`, as today |
| eval: `regression` and `unplanned improvement` in one cell | `regressed`; confirmation re-checks the regression fact; a reproduced regression stays `regressed`, a disputed one is `inconclusive`; the improvement never decides |
| eval: intended `holds -> fails` (listed in `intent.md`) | existing behavior, unchanged |
| eval: cached cell stored `regressed` or `inconclusive` whose only non-held moves are unlisted improvements | reclassified `improved` from the stored outcomes, stored confirmation ignored; record and report updated; zero model calls |
| eval: cached mixed cell whose stored confirmation reproduced only the improvement | stays `inconclusive`; the regression fact must be re-checked by a fresh confirmation under the normal path |
| eval: cached cell stored `error`, or missing per-fact outcomes | not reclassified; existing recovery path |
| eval: cached evidence identity mismatch | existing refresh path (replay / re-judge); reclassification does not apply |
| eval: run with zero model calls and changed verdicts | record and `report.md` rewritten; a second identical run writes nothing |
| eval: reclassification record write fails | caught on that path; exit 1; `report.md` unchanged |

## Risks

- Plan phase slows by one test run per task; if consumer repos show minute-scale runs, fall back to one union run with per-task attribution (approach 3 in the brainstorm).
- The plan-writer becomes an executor; `bash` is scoped by prose, not by tooling.
- A `baseline:` bullet is model-authored text; the implementer's own `SCOPED_TEST_COMMANDS` run remains the verification. The provenance check (allowed-edit classification, unchanged base before and after) bounds what the bullet can claim; the no-authoring rule routes every missing bullet back through a run.
- The jj provenance form is specified from `jj log`/`jj diff` as the seal already uses them; a jj consumer is the first live check of its `@-` base choice.
- Introduced-selector matching reads the task's own step text; a task that names its new test loosely runs the selector unchanged and records a zero-test failure row, which the narrow option resolves.
- `replay.md` role clauses change the assembly for every existing `writing-plans` cell, and the raised `wordCap` admits longer replies target-wide; one full run per target.
- An `unplanned improvement` can mask a sample whose fact was too loose to begin with, or an `intent.md` entry written in the wrong direction; the label stays visible in `report.md` so a reviewer can tighten the fact or fix the entry, and a `regression` on any other fact still blocks.
- The preserved Wave 1 patches from the first implementation pass were produced under the old acceptance policy; they are integrated only after passing their reviews under this spec, never accepted on the strength of the policy change.
