# Housekeeping eval

Replay one selected checkpoint with no tools. `directory-three-picks` tests a directory card's Fix, Ticket and Ignore choices and the promise of a separate PR for the class. It loads the new spine, selection and card rules plus the shared menu, eligibility and register rules. It drops rule compilation and base-rule data because the checkpoint supplies validated findings.

Run `node eval/run.mjs housekeeping directory-three-picks --base 92eb7a087670521a6117c5e39c06066de0a5bbc7` only within the spec's three-invocation per-sample bound. Replay saved evidence locally with `node --test eval/housekeeping/directory.test.mjs`; this check makes no model or external call and rejects stale or failed candidate replies and judgments.

`feature-branch-stop` tests the already-defined admission stop for a directory run on a feature branch: stop before Check, explain the branch requirement, name the PR input and retain the run-folder path. Its bundle contains only the spine and Select. Run `node eval/run.mjs housekeeping feature-branch-stop --base 92eb7a087670521a6117c5e39c06066de0a5bbc7` within the same three-invocation per-sample bound. Replay it locally with `node --test eval/housekeeping/feature-branch-stop.test.mjs`; the test also asserts the shared directory/no-argument admission clauses.

`pr-card-no-ticket` supplies a draft-PR card checkpoint with only Fix and Ignore and a one-commit push to the existing PR branch. Run `node eval/run.mjs housekeeping pr-card-no-ticket --base 92eb7a087670521a6117c5e39c06066de0a5bbc7` within its three-invocation bound. Its local check, `node --test eval/housekeeping/pr-card-no-ticket.test.mjs`, also asserts clean remote-head admission, dirty/diverged stops, PR file selection and one-commit-per-class delivery. It rejects missing saved replies; this sample has no captured replay evidence.

Coverage is partial: selection is a conformance read of `reference/select.md`, not live Git execution; only the feature-branch directory stop has a rendered admission replay, not the no-argument or PR stop. The approved delivery, repair/undo and ticket-handoff checks are documentation assertions over `skills/housekeeping/reference/fix.md`, outside the card replay bundle. No PR, push, ticket, worktree or in-place delivery is exercised. Four approved samples have no fixtures. `report.md` describes the last selected run; completed samples retain their own records under `results/`. Deterministic checks live beside this target; the repository has no separate slow-tier convention for them. See [the eval process](../README.md).
