# Expected facts: gh-8-shape-ticket-skill

- f1: Delivery teams inherit tickets that prescribe solutions without a verifiable outcome.
- f2: Users gain a tracker-neutral tool for creating or repairing one actionable issue at a time.
- f3: Every tracker write requires explicit approval of the proposed changes.
- f4: An unmeasurable improvement claim in the acceptance criteria blocks all writes until it is resolved.
- f5: An already conforming ticket is left unchanged.
- f6: If a ticket changes during approval, the revised proposal must be approved again before it is written.
