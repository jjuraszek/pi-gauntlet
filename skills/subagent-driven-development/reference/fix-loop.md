# Escalated fix rounds

**Escalate** = one escalated round; stop only on failure. Call `gauntlet_setting({ key: "escalationLoop" })` (unavailable -> stop and report). `implModel` undefined -> stop note. Otherwise re-dispatch that fix - same payload and isolation knobs (`cwd`, `worktree`, `SCOPED_TEST_COMMANDS`, status protocol, prior patch, spec anchors) plus the prior report verbatim - overriding only `model: <implModel>`, `context: "fresh"`, `async: false`; one implementer, no fan-out. Run the normal fix-round review gate (SR then CR on `Behaviour-change: yes`, else the triggering reviewer with the re-review marker). All clean -> proceed; the escalated patch supersedes the prior one at integrate. A non-`DONE` status or a dispatch error -> stop note per `stop-note.md`. A review with issues -> a funded round while one remains for the task (below), otherwise stop note; no other second dispatch. Once per loop; independent of the convergence exception. No `plan_tracker` write during escalation - keep the task `in_progress` until the wave commit or, on a stop, the human decides.

## Funded rounds

Decode the current `**Amend-grant:**` line using **Value decoding** in [Standing grants](../../brainstorming/reference/amendment-surface.md#standing-grants) before each funded dispatch. Funding is independent of ordinary fixes and the escalated round; it never supplies a missing `implModel`, another escalation grant, verify credits, or `grant_fix_rounds`. Keep the review-3 convergence exception once per loop; never re-arm it through funding.

Start one per-task ledger at zero when each task first enters Fix-Loop Rounds. Carry it across SR, behavior-change reroutes, the SR-to-CR transition, and wave repairs re-entering SR; use no wave-level allowance. Determine touched owners using the SR targeting rule (tasks whose files the fix touches). For a multi-task CR repair, spend once from every touched task; a touched exhausted owner stops the wave with that task's stop note before dispatch.

Before every funded dispatch, print `funded round <k> of <N> for task <n>` for each touched task. Apply mid-loop grants prospectively, with spent starting at zero: rounds before the token was written neither count against nor toward it. Repeat the escalated payload and isolation exactly: configured `model: <implModel>` from `escalationLoop`, `context: "fresh"`, `async: false`, one implementer, no fan-out, same `cwd`/`worktree`, task text, prior patch, spec anchors, status protocol, `SCOPED_TEST_COMMANDS`, and complete prior report verbatim. Run the same tests and same review gate: SR then CR on `Behaviour-change: yes`, otherwise the triggering reviewer with the re-review marker, trajectory block and Fix delta. Every dispatched round spends one, including failures.

| Funded outcome | Action |
|---|---|
| Errors and non-`DONE` | Count as spent and stop with the task's stop note. |
| Any funded re-review reports `STAGNANT` | Stop immediately regardless of funding remaining. |
| Issue-bearing re-review with rounds left | Dispatch the next funded round. |
| Issue-bearing re-review after N rounds | Stop with the exhausted task's stop note. |
| All reviews clean | Continue through the wave gate and commit before task completion. |

Emit the task's stop note for the funded-stop outcomes above (including `STAGNANT`) and an escalated-round failure with no funded round left. While a budget token exists, include `budget: <spent> of <N> spent` in every stop note after `Problem:` and any `Searched:` lines and before the file finding, including pre-escalation stops, missing `implModel`, and exhausted fact lookups at spent zero; use the `(not recovered on resume)` suffix below when recovery fails, and omit the line without a token. Treat this line as the only round-history exception to `stop-note.md`'s no-round-history rule.

On resume, keep header restoration unchanged; recover each task's spent count only from its `funded round <k> of <N>` transcript lines. Without recoverable lines, treat funding as exhausted; stop the next issue-bearing re-review with `budget: <N> of <N> spent (not recovered on resume)`. Treat a newly written budget token as the human refund, never a resume reset. Use no new spent carrier or handoff/resume grammar.

## Implementer-failure stops

Use this procedure for execution failures, not review escalation. Preserve review convergence, `grant_fix_rounds`, STAGNANT/REJECT handling, and the funded ledger above. At every execution stop, decode the current `**Amend-grant:**` through **Value decoding** in [Standing grants](../../brainstorming/reference/amendment-surface.md#standing-grants). Absent, `none`, or budget-only values supply neither automatic decisions nor execution escalation; retain the ordinary two-attempt stop and status routing. Keep fact lookups in their documented order per [stop-note.md](../stop-note.md); permission never bypasses exhausted or inaccessible lookups.

Apply these steps in order under amend permission:

1. **Hard stops**: stop before grant-driven dispatch on malformed grants, missing `implModel`, unavailable settings tools, dirty-tree or commit-boundary returns, empty-commit stagnation, cap, funded re-review `STAGNANT`, or `REJECT`. Preserve redraw stops for ticket rows, row add/remove, reviewer-only or taste objections, problem statement changes, and component boundary changes. Use the existing stop/report route, not a recommendation to bypass it.
2. **Takeable decision**: render `Recommendation: <option> - <why>` for a named concrete change. Compare its evidence with already auto-resolved evidence on this task: normalize whitespace in the quoted `file:line` finding or failing command plus assertion from the implementer return. Recover earlier evidence from the transcript; use no new evidence file. On a match, print `Recommendation: none - evidence repeats task <n>` and wait. For a `BLOCKED`/`NEEDS_CONTEXT` decision, route by the table below before considering escalation. For an execution failure at two failed attempts with no takeable decision, continue to step 3; after its failure, route the resulting decision through the table.
3. **Execution escalation**: after two failed attempts, resolve `gauntlet_setting({ key: "escalationLoop" })`; tool failure/unavailability stops and reports, `implModel` undefined stops with the existing note. Before attempt 3 print `escalated round for task <n> after 2 failed attempts`. Dispatch one implementer with `model: <implModel>`, `context: "fresh"`, `async: false`, no fan-out: same payload and isolation (`cwd`, `worktree` mode, original task, prior patch, spec anchors, status protocol, `SCOPED_TEST_COMMANDS`, complete prior report verbatim). Retain accepted siblings; never re-chain. This is one execution escalation per task at this site, independent of review escalation and funding; no ledger spend or review allowance changes.
4. **Resulting decision**: a dispatch error or non-`DONE` spends the escalated round. Apply step 2 to its resulting decision, including an authorized spec amendment, then stop for none/budget/consent recommendations; no fourth unnamed repair. Success still runs the ordinary scoped tests and SR/CR gates before wave commit and task completion. Keep `in_progress` until then.

| Recommendation | Action |
|---|---|
| Named in-task repair within remaining ordinary attempts | Print `took recommendation: <option> for task <n>` and re-dispatch with that option and evidence; count every re-dispatch as an ordinary attempt under the two-attempt limit. Preserve payload and isolation. |
| Named spec/plan rule edit, including a drafted AC row text correction backed by quoted implementer test/assertion/code evidence | Enter [amendment-surface](../../brainstorming/reference/amendment-surface.md) section 5 under the grant; quote the worker evidence, perform its plan/check/tracker aftermath and granted audit. Do not treat amendment permission as another attempt allowance. |
| `fix-first` | Enter `/skill:shape-ticket`; stop at its write gate, never auto-repair unrelated work. |
| `none`, more rounds/attempts, `cap +N`, consent, a separate change, or redraw | Emit the stop note ending in `Recommendation: <option> - <why>` (or `none`) and wait. Budget or consent advice never authorizes itself. |

On resume, recover the exact site identity only from `escalated round for task <n> after 2 failed attempts` in the matching task's transcript, not a review escalation or sibling line. A matching line means spent; unrecoverable means spent, so missing history never authorizes another escalation. A mid-loop grant or explicit retry never re-arms this site. Recover auto-taken evidence from that task's transcript too. Keep funded-round recovery and its budget placement/suffix unchanged.
