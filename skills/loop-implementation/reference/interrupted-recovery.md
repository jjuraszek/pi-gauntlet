# Interrupted recovery

Treat dispatch error, non-DONE, silence kill, dirty tree, zero/multiple commits and wrong attribution as interrupted returns. Use the saved pre-dispatch ledger and checkout `HEAD_BEFORE`; on resume use the tuple's HEAD and its ledger before-image (the saved home HEAD for a companion). Recover without a human turn under approval options 4 and 5 alike. Recovery itself is unconditional; check the numbered target's effective allowance or seed repair count only after committing the repair.

1. Read `${TMPDIR:-/tmp}/loop-<base SHA>-<iteration i>.jobs`; process lines are `<pid> <process-start-identity> <command>`. An absent or empty jobs file means no jobs to terminate. For each listed live job require matching start identity and command plus PGID equal to the pid; recheck identity, command and group leader before each signal. Send `kill -TERM -- -<pid>`, wait at most 10 s, then send `kill -KILL -- -<pid>` to a surviving matching group. When any identity, command or group-leader check fails, identity is unavailable, or the job is already gone, skip that job and continue recovery. A job still alive after KILL does not block recovery. Signal neither the driver's shells nor unrecorded processes. Print `terminated <k> child jobs` when k > 0, counting observed exits, then delete the jobs file.
2. Use the driver's shell: `git -C "<worktree>" reset --hard HEAD_BEFORE`, then `git -C "<worktree>" clean -fd` (leave ignored files alone). Continue even when files remain after reset; the next return is validated as usual.
3. Write the ledger from the saved copy with `iterations:` = saved +1 and no `pending:`. For a numbered target set only that row `failed`, attempts = saved attempts +1, evidence `iteration <i>: interrupted - <reason>`; preserve every other row and all prior decisions, including spent escalation. Use `killed after silence`, `dispatch error: <text>` (for any tool-reported `error: <text>` such as `Request aborted`, even when the return file is empty), `dirty tree`, `<k> commits`, `wrong attribution` or `non-DONE` (for a completed non-error return lacking DONE) as the concrete reason. Commit `loop: repair row <n>`, refresh and return to the ordered table in the same turn; rule 2 stops a repaired row at allowance. For seed leave every row cell and decision unchanged, commit `loop: repair seed` with `seed interrupted: <reason>` in the body, refresh and apply the seed count in ## Validate the return. Never append a fabricated child decision.

Failure pass: when `git -C "<worktree>" rev-parse HEAD` differs from `HEAD_BEFORE` after step 2, or the step 3 commit is not written, dispatch nothing and run steps 2-3 again from the saved copy. Count each pass once more against the same allowance: the row's effective allowance, seed count or verification repair count, held with the saved copy while no commit can land. End the passes when a ledger-only repair commit lands on `HEAD_BEFORE`, recording the one consumed attempt as step 3 states, or when the held count reaches the allowance; render the existing row, seed or verification exhaustion stop with that count. Stage only the ledger path for the repair; never use any other HEAD as the next dispatch's `HEAD_BEFORE`.

For a companion apply [coordinated recovery](coordinated-legs.md#companion-return-validation) to its checkout and write the repair only in home.
