# Empty-child stagnation

List home commits with `git log -G'^returned: ' --format=%H <base>..HEAD -- <ledger path>` and compare each ledger's `returned:` value to its first parent's; keep only changes to a non-`none` tuple. For tuple `<target> | <repo> | <S>`, find the first commit from `git -C <owning checkout> rev-list --reverse --ancestry-path <S>..HEAD`, then its changed paths with `git -C <owning checkout> show --format= --name-only <worker sha>`. Use the companion checkout for companion objects; stop naming any failed read rather than treating it as no files. Read home row status before/after from the ledger at S and worker SHA for home, or the listing commit's first parent and listing commit for companions. Include a return in the window only when its dispatch ledger already holds the starting decision: at S for home, at the listing commit's first parent for companions. A later repair cannot move an older worker into a new window. Set the hint only when the last two workers for that row each changed no file outside the ledger and no row status. Exclude seed and parent commits; a decision alone is not progress. A pending human `retry <n> | <hint>` for that row wins over the fixed hint. Attach a rule-3 hint only to its row; a cut row or a different selected target carries none. Pass the selected row's hint in the existing `hint:` task field.
